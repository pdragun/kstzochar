# Security

Read before changing sign-in, admin access, HTML sanitizing, response headers or GPX downloads. `AGENTS.md` has the rules most changes need.

- **Auth**: built-in `form_login` against `User` by email (`config/packages/security.yaml`, `LoginController`). `ROLE_ADMIN` inherits `ROLE_USER`. `login_throttling` refuses logins after 5 failed attempts in 15 minutes (counted in `cache.rate_limiter`, which `LoginFormTest` clears in `setUp()`); logout needs a CSRF token, so link to it with `logout_path()`, not `path('logout')`. `AdminAccessTest` lists every admin URL and checks that a member (`jana.novakova@example.com`) gets 403: add new write actions there.
- **HTML sanitizing and headers**: the CKEditor `content` of invitations, chronicles and blogs is cleaned by the `app.article_sanitizer` HTML sanitizer (`config/packages/html_sanitizer.yaml`: safe elements plus `style` and `class`, no iframes, no input length limit) twice: on save (the form fields' `sanitize_html` option) and on render (`|sanitize_html('app.article_sanitizer')` instead of `|raw`, which also covers older rows). Saving stores HTML entities as plain characters. `App\EventListener\SecurityHeadersListener` adds `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy` and a `frame-ancestors` CSP to every response (a listener, because production runs on Apache); in debug mode Symfony removes the CSP header from error pages.
- **GPX**: `App\Service\Gpx` wraps `sibyx/phpgpx` to sanitize uploaded GPX tracks (it resets metadata and author) before `GpxController` serves them. `/gpx/{id}` serves a route only when it belongs to a published invitation or chronicle (admins get every route), because routes stay in the database after they are removed from content.
